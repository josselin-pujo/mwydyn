# 13 — Blob refs ratified: tag 1002, hash-bound media types

> Status: DECIDED and implemented (2026-11-08). Amends
> [spec-v0](../docs/spec-v0.md) §1 (profile v0.1), §4 (DECIDED);
> [world-v0.wit](../docs/world-v0.wit) comment. Gates green.

## 1. The decision (owner)

- **Hash-bound + tag 1002, ratified.** On cross-type dedup: *"no,
  there is no case where we would want to dedup that — if they have
  different mime types, they are not the same content, even if their
  body is the same, because they don't have the same type — that's
  the point of hashing the mime type. If content-identity happens
  it's a collision, not a desired state."*
- Owner's law in §4: **content identity includes type**; plus the
  general law this round produced: **anything claimed outside the
  hash is mutable-by-transit.**

## 2. Implemented (mwydyn-data, profile v0.1)

- `Value::BlobRef { digest, media_type, size }` — tag 1002, decoded/
  encoded; shape validated at the barrier (64-char lowercase hex
  digest, non-empty type; uppercase and non-hex reject at decode).
- `blob_digest(bytes, media_type)` — SHA-256 over the canonical CBOR
  of `{bytes, type}` (canonical key order by length-first rule falls
  out of the existing profile: type before bytes). `blob_ref()`
  builds a full ref; `validate_blob_ref()` for externally supplied
  fields. Dep: `sha2`.
- Encode is a SERIALIZER, not a validator — forged refs must be
  encodable so rejection vectors can exist (the debug_assert learned
  this the hard way: attacker bytes are corpus material).
- Store-side ripple (M3): the store holds the (type, bytes) pair;
  `get` verifies digest on read — integrity checking inherited for
  free.

## 3. Vectors

tag-of-map-of-wrong-arity), forged-uppercase-digest decode rejection.
